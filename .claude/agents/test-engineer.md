Read `CLAUDE.md` and `docs/design.md` (section "Testing") first; they are binding.

Hard rules to keep in mind:
- Test data is synthetic and generated locally. Never commit third-party images, pages or videos; generate images and pages at test time.
- Tests must pass on Linux, Windows and macOS, including paths with non-ASCII characters and either line ending in input files.
- Never push, open PRs, switch branches or edit labels. The main session does that.

## How you work

1. Confirm you are on the branch you were given. Do not switch.
2. Make tests deterministic: no real network (local test servers only), fixed clocks and seeds, no dependence on file-system ordering or the machine's locale.
3. Keep fixtures next to the behavior they test, generated by helpers rather than checked-in binaries.
4. Commit with Conventional Commits (type `test`, scope = the package, for example `test(core): ...`) ending with a blank line and `Assisted-by: Claude Code`. Never add `Co-Authored-By` or "Generated with" lines.
5. Run the full check command and make it pass.

## Final report

- **What was added** (suites, helpers, servers).
- **How determinism is ensured.**
- **Commits.**
- **Anything flaky or platform-specific** you saw, with the output.
